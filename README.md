# AI Advent Challenge — День 6. Первый агент

Web-чат с независимо настраиваемыми агентами: **Архитектор ПО** и **Повар-помощник**.
У каждого агента может быть несколько чатов. История каждого чата сохраняется на сервере,
восстанавливается после перезапуска приложения и передаётся в LLM при продолжении разговора.

## Как пользоваться

1. Выберите помощника в списке.
2. Нажмите «Новый чат» или откройте существующий диалог.
3. Напишите сообщение и нажмите «Отправить» (либо Cmd/Ctrl + Enter).
4. Продолжайте разговор: агент получает только историю выбранного чата.
5. Для новой темы создайте отдельный чат.

Ответы отображаются в Markdown с временем запроса и токенами. При ошибке текст остаётся
в поле ввода для повторной отправки; прежняя история не меняется. Если ответ достиг лимита,
UI предложит попросить агента продолжить.

## Архитектура

- Java 21 + Spring Boot: REST API и Spring AI/OpenAI HTTP-клиент.
- React JavaScript + Vite: выбор агента, список его чатов, окно диалога.
- `Agent` — отдельная сущность. `ConfiguredAgent` инкапсулирует формирование контекста,
  проверку лимита, вызов модели и обработку ответа.
- `AgentRegistry` создаёт отдельный экземпляр агента для каждого YAML-файла.
- `ChatService` управляет чатами, блокирует одновременную отправку в один чат
  и сохраняет завершённую пару сообщений.
- `ChatRepository` отделяет хранение истории от агента. Реализация `FileChatRepository`
  записывает каждый чат атомарно в отдельный JSON-файл.
- Контекст запроса: системный промпт выбранного агента → все сохранённые сообщения
  текущего чата с ролями user/assistant → новое сообщение пользователя.

Провайдер получает историю через Chat Completions; история других чатов не подмешивается.
Приложение поддерживает много агентов в **одном JVM-процессе**, с общей границей в четыре
одновременных вызова LLM и одним вызовом на чат. Это персональная лаборатория без
авторизации: чаты разделены по агентам и диалогам, но не по учётным записям пользователей.
Файловое хранилище не предназначено для нескольких одновременно пишущих экземпляров приложения.

## Конфигурация агентов

Встроенные определения:

- `src/main/resources/agents/architect.yaml`
- `src/main/resources/agents/chef.yaml`

Каждый файл содержит:

```yaml
id: architect
name: Архитектор ПО
description: Помогает проектировать программные системы.
model: gpt-4.1-mini
max-completion-tokens: 4096
timeout-seconds: 120
max-history-chars: 60000
system-prompt: |
  Здесь системный промпт агента.
```

Можно добавить `reasoning-effort: low` для GPT-5. Поддерживаемые значения:
`low`, `medium`, `high`; для GPT-4 это поле нужно опустить.
Лимит `max-completion-tokens` задаётся от 64 до 32768, таймаут — от 1 до 300 секунд.
Выбирайте параметры, поддерживаемые указанной моделью и вашим OpenAI API-аккаунтом.
Параметры модели и системный промпт нельзя переопределить из браузера.

`max-history-chars` — предел суммарного числа символов системного промпта, истории
и нового сообщения (от 1000 до 200000). Это ограничение приложения, а не точный подсчёт
контекстных токенов модели. При его достижении приложение просит создать новый чат,
сохраняя прежнюю историю. Сообщения не обрезаются молча.

### Добавить агента без пересборки

Скопируйте определения в отдельный каталог и укажите glob через переменную окружения:

```bash
mkdir -p config/agents
cp src/main/resources/agents/*.yaml config/agents/
export AGENT_CONFIG_LOCATION="file:./config/agents/*.yaml"
```

Добавьте в этот каталог ещё один YAML-файл с уникальным `id`, именем, описанием,
моделью и системным промптом. Перезапустите приложение: агент появится в UI.
Внешний каталог **заменяет** встроенный набор. Неправильная конфигурация или повторяющийся
`id` останавливают запуск с ошибкой; исправьте файл, затем повторите запуск.
Изменение конфигурации применяется после перезапуска, в том числе к следующим сообщениям
существующих чатов. `id` связывает агента с его историей — не меняйте его без необходимости.

## Хранение

По умолчанию: `data/agent-chats/<agent-id>/<chat-uuid>.json`.
Путь переопределяется переменной `CHAT_DATA_DIR`. Для VM рекомендуется абсолютный путь:

```text
CHAT_DATA_DIR=/opt/ai-advent-challenge/data/agent-chats
AGENT_CONFIG_LOCATION=file:/opt/ai-advent-challenge/config/agents/*.yaml
```

Каталог должен быть доступен на запись пользователю systemd-сервиса. Старые файлы данных
предыдущих заданий не удаляются и не используются новым хранилищем. Для резервного копирования
сохраните каталог `agent-chats` и внешние YAML-конфигурации.

При повторе уже успешно сохранённого сообщения с тем же `messageId` приложение возвращает
историю без нового обращения к LLM. В случае аварии между ответом провайдера и сохранением
файла повтор может вызвать LLM повторно. Автоматические HTTP-повторы провайдера отключены.

## API

| Метод | Путь | Результат |
| --- | --- | --- |
| GET | `/api/agents` | Агенты и публичные настройки |
| GET | `/api/agents/{agentId}/chats` | Список чатов агента |
| POST | `/api/agents/{agentId}/chats` | Новый пустой чат |
| GET | `/api/agents/{agentId}/chats/{chatId}` | История выбранного чата |
| POST | `/api/agents/{agentId}/chats/{chatId}/messages` | Ответ агента и обновлённая история |

Тело отправки сообщения:

```json
{
  "messageId": "9c0a1e79-e6e4-456b-a30d-c939fbce779a",
  "content": "Спроектируй архитектуру интернет-магазина"
}
```

`messageId` — новый UUID для нового сообщения; при повторе неуспешной сетевой отправки
используется прежний UUID. Длина сообщения: 1–12000 символов.
Ошибки возвращаются в виде `{"message":"..."}`: 400 — неверный запрос/лимит контекста,
404 — неизвестный агент или чат, 409 — занят чат/достигнут лимит параллельных вызовов,
502 — ошибка LLM, 500 — ошибка сохранения. Чат другого агента возвращает 404.

## Разработка и проверки

Нужны Java 21, Maven 3.9+ и `OPENAI_API_KEY`.
Maven устанавливает Node.js, собирает React и включает его в один runnable JAR.

```bash
export OPENAI_API_KEY="ваш-api-ключ"
mvn spring-boot:run
```

Приложение: <http://localhost:8080>. Для отдельного frontend dev-сервера:

```bash
cd frontend
npm ci
npm run dev
```

Vite: <http://localhost:5173>, запросы `/api` проксируются на `localhost:8080`.
Проверки из корня проекта:

```bash
npm --prefix frontend test
npm --prefix frontend run build
mvn test
mvn package
```

Тесты используют временное хранилище и замену LLM, не расходуя OpenAI-токены.
Проверяются сохранение/восстановление, изоляция историй, роли и порядок контекста,
YAML-конфигурация, повтор отправки, ошибки и UI.

## Логи

```bash
sudo journalctl -u ai-advent-challenge -f
```

События `agent_request`, `llm_started`, `llm_completed`, `agent_response` связаны
по `requestId` и `chatId`. Видны агент, модель, размер истории, количество вызовов,
токены и время; текст диалога, системный промпт и секреты не логируются.
Один `llm_started` соответствует одному вызову HTTP-клиента без автоматических retries.

## Production-сборка

Из корня проекта выполните:

```bash
mvn clean package
```

Эта команда запускает `npm ci`, собирает React, выполняет Java-тесты и создаёт единый runnable JAR:

```text
target/ai-advent-challenge-0.0.1-SNAPSHOT.jar
```

Локально production-артефакт можно запустить так:

```bash
export OPENAI_API_KEY="ваш-api-ключ"
java -jar target/ai-advent-challenge-0.0.1-SNAPSHOT.jar
```

## Деплой и запуск на `cloudvm`

На виртуальной машине уже должны существовать:

- Java 21;
- systemd-сервис `ai-advent-challenge.service`;
- Nginx, проксирующий HTTP-запросы на `127.0.0.1:8080`;
- защищённый `/etc/ai-advent-challenge.env` с `OPENAI_API_KEY` и настройками proxy.

Файл `/etc/ai-advent-challenge.env` нельзя копировать из репозитория, перезаписывать или выводить в лог. Его ожидаемые права — `0600`.

Сначала соберите приложение локально:

```bash
mvn clean package
```

Загрузите JAR во временный файл:

```bash
scp target/ai-advent-challenge-0.0.1-SNAPSHOT.jar \
  cloudvm:/tmp/ai-advent-challenge.jar
```

Установите артефакт и перезапустите сервис:

```bash
ssh cloudvm '
  set -eu
  sudo install -o vlad -g vlad -m 0644 \
    /tmp/ai-advent-challenge.jar \
    /opt/ai-advent-challenge/ai-advent-challenge.jar
  rm -f /tmp/ai-advent-challenge.jar
  sudo systemctl restart ai-advent-challenge
'
```

Проверьте приложение без расходования OpenAI-токенов:

```bash
ssh cloudvm '
  sudo systemctl is-active ai-advent-challenge
  sudo systemctl is-active nginx
  sudo ss -ltn "sport = :8080"
  curl --fail --silent http://127.0.0.1/
  curl --fail --silent http://127.0.0.1/api/agents
  sudo journalctl -u ai-advent-challenge --since "5 minutes ago" \
    --no-pager -p err -q
'
```

Java должна слушать только loopback-интерфейс `127.0.0.1:8080`; внешний трафик обслуживает Nginx. Проверка конфигурационного endpoint не вызывает OpenAI API и не расходует токены.
