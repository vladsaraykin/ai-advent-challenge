# Запись работающего приложения

## Выбор инструментов

Используй доступный browser/computer tool или установленный Playwright. Если их нет, для локального Chrome подходит Chrome DevTools Protocol через WebSocket и `Page.captureScreenshot`. Наличие Node.js и Chrome ещё не означает доступность Playwright: сначала проверь окружение. Не добавляй зависимости записи в package.json приложения.

Запускай отдельный браузер с уникальным временным `user-data-dir`, свободным debug-портом на loopback и фиксированным viewport. Для временной папки используй `mktemp -d`; не полагайся на пути от прошлой сессии. Не открывай debugging-порт наружу и не считывай личный профиль браузера.

Проверь URL, порт и авторизацию. Для локального Vite учитывай IPv6 `::1`. При запрете сетевого доступа в sandbox запроси штатное разрешение на нужную команду. Не считай работающий listener доказательством, что HTTP-запрос из sandbox разрешён.

Регистрацию/вход выполни до начала записи, если показ авторизации не нужен. Не записывай пароль, Authorization, API-ключи или содержимое env. Если создаёшь пароль, сгенерируй случайный; сохраняй его только при необходимости, отдельно от видео и сценария, с ограниченными правами.

## Сценарий как исполняемые шаги

Подготовь небольшой управляющий скрипт под текущую версию UI. Отдели команды `caption`, `click`, `fill`, `waitFor`, `assertState`, `capture` от последовательности сценария. Сохраняй выполненные шаги и индексы кадров, чтобы продолжать после сбоя без перезаписи и повторных платных вызовов.

Предпочитай доступные имена и labels. Проверяй существование и доступность кнопки. Прокручивай элемент в видимую часть экрана и выполняй реальные input-события. Покажи указатель или подсветку клика, поскольку скриншоты страницы обычно не содержат системный курсор.

Для React `element.value = ...` может не обновить controlled state. Используй Playwright `fill` или ввод через браузер; в CDP fallback можно вызвать нативный setter input/textarea и событие `input`/`change`. Подтверждай изменение значения и доступность отправки до клика.

Дожидайся завершения SSE, обновления памяти и снятия loading, а не только появления первого текста. После этого проверь отсутствие ошибки и нужное состояние. Ограничь ожидание тайм-аутом с учётом лимитов сервиса. Паузы для чтения титров не заменяют проверку готовности.

В CDP возвращай из `Runtime.evaluate` сериализуемые значения: строки, числа, JSON или `Boolean(...)`. Возврат DOM-элемента с `returnByValue` может вызвать `Object reference chain is too long`. После reload контекст может временно исчезнуть: переподключись или дождись DOM, восстанови титры. Запись промежуточных кадров должна переносить кратковременные ошибки reload, но не скрывать длительный обрыв связи.

## Текстовые вставки

Выдели полосу под титры, не перекрывающую поле ввода, кнопку или ошибку. Допустимо уменьшить рабочую высоту приложения только на время записи. Подойдут 1600×1000 или 1920×1080, контрастный фон и основной текст примерно 22–28 px; проверь результат на реальном кадре.

Показывай номер/название шага и одну-две фразы. Оставляй время на чтение. При отсутствии озвучки титры должны самостоятельно объяснять демонстрацию. Не называй проверку успешной до появления фактического результата.

Браузерный overlay удобен, когда FFmpeg собран без `drawtext`/`subtitles`: проверь фильтры перед выбором способа. DOM overlay добавляй изолированно с уникальным id и `textContent`, не изменяя исходники приложения. Это только оформление записи.

## Кадры и монтаж

Предпочитай штатную запись Playwright/CDP screencast. При покадровом fallback сохраняй кадры последовательно и время каждого кадра; не запускай наложенные screenshot-вызовы. Восстанови длительности по timestamps, например через FFmpeg concat manifest с `duration`. Фиксированный `-framerate` корректен только при равномерной выборке или сознательном изменении скорости.

Для равномерной последовательности JPEG по 4 кадра/сек пример сборки из рабочей папки артефактов:

```sh
ffmpeg -hide_banner -n -framerate 4 -i frames/%06d.jpg \
  -c:v libx264 -preset medium -crf 19 -pix_fmt yuv420p \
  -r 24 -movflags +faststart demonstration.mp4
```

24 fps в выходном файле не превращают покадровую запись в плавную запись мыши. Если нужна плавность, записывай больше исходных кадров. Сокращение ожиданий допустимо, но обозначь ускорение/монтаж; не используй смонтированную длительность как измерение скорости модели.

Не вставляй необработанный текст пользователя в shell-команды или FFmpeg-фильтры. Используй аргументы процесса или отдельные файлы. Не перезаписывай исходные кадры при возобновлении: продолжай нумерацию либо создай отдельный сегмент.

## Проверка и выдача

```sh
ffprobe -v error -show_entries format=duration,size:stream=codec_name,width,height,r_frame_rate \
  -of json demonstration.mp4
ffmpeg -v error -i demonstration.mp4 -f null -
```

Посмотри кадры готового видео в начале, возле ключевого отказа, после паузы и в конце. Проверь читаемость, корректную последовательность, отсутствие секретов и пустых экранов. В итоговой папке сохрани MP4 и сценарий с фактическими отклонениями. Приватные данные входа не включай в эти артефакты.

Закрой созданный браузер через `Browser.close` или останови принадлежащую записи сессию. Не останавливай сервер пользователя. Временные исходники не удаляй рекурсивно по широкому пути; оставь их для восстановления, если безопасная уборка не требуется.
