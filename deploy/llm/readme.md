# Qwen 3.5 9B — запуск MLX-сервера

## Запуск

Активировать окружение:

```bash
source ~/venvs/mlx/bin/activate
```

Проверить, что используется ARM64:

```bash
uname -m
```

Должно быть:

```text
arm64
```

Запустить сервер:

```bash
mlx_lm.server \
  --model mlx-community/Qwen3.5-9B-4bit \
  --host 127.0.0.1 \
  --port 18081
```

API будет доступен по адресу:

```text
http://127.0.0.1:18081/v1
```

## Остановка

В терминале, где запущен сервер:

```text
Ctrl+C
```

После остановки процесса модель выгружается из памяти.

## Выйти из окружения

```bash
deactivate
```

## Подключение к приложению (День 27)

После первоначального скачивания модели можно запускать MLX из кеша без обращения
к Hugging Face: задайте `export HF_HUB_OFFLINE=1` в терминале MLX перед запуском сервера.

Spring Boot занимает порт 8080, MLX — 18081. Проверка модели:

```bash
curl -fsS http://127.0.0.1:18081/v1/models
```

Перед запуском backend в отдельном терминале:

```bash
export LOCAL_LLM_BASE_URL=http://127.0.0.1:18081/v1
export LOCAL_LLM_MODEL=mlx-community/Qwen3.5-9B-4bit
export LOCAL_LLM_MAX_TOKENS=4096
export LOCAL_LLM_CONCURRENCY=1
export LOCAL_LLM_THINKING=false
export MCP_ENABLED=false
unset OPENAI_API_KEY
mvn spring-boot:run
```

Также нужны существующие настройки PostgreSQL (RAG_DATABASE_URL, RAG_DATABASE_USERNAME,
RAG_DATABASE_PASSWORD). Для RAG нужны Ollama и reranker; они не являются облачными LLM.

UI: `cd frontend`, `npm ci`, `npm run dev -- --host 127.0.0.1`.
Откройте http://localhost:5173, авторизуйтесь, выберите агента и **Local MLX**
в поле «Провайдер LLM». Выбор сохраняется в настройках чата, его можно менять между запросами.
Повторная отправка и продолжение MCP используют провайдера из исходного снимка запроса.

Основной ответ, память, summary, facts, guards и RAG rewrite выполняются локально.
Облачного fallback нет. При остановке MLX отображается ошибка и сохраняется возможность повтора.
Для Qwen не показываем подсчёт отдельных частей промпта OpenAI-токенизатором.
Точные input/output/total берём из MLX usage, при его отсутствии показываем отсутствие данных.
Нулевая стоимость означает отсутствие платы API; электричество и оборудование не оцениваются.

Настройки в `app.llm.local` (`application.yml`): `LOCAL_LLM_ENABLED`, `LOCAL_LLM_BASE_URL`,
`LOCAL_LLM_MODEL`, `LOCAL_LLM_MAX_TOKENS`, `LOCAL_LLM_TIMEOUT_SECONDS`,
`LOCAL_LLM_CONCURRENCY`, `LOCAL_LLM_TEMPERATURE`, `LOCAL_LLM_THINKING`, `LOCAL_LLM_TOOLS_ENABLED`.
Температура обычного ответа по умолчанию 0.3, для JSON-вызовов — 0; thinking отключён, чтобы вспомогательные JSON-вызовы
не тратили лимит ответа на рассуждения. MLX не обеспечивает JSON mode: результат
проверяют существующие серверные валидаторы; неверный JSON не сохраняет ход.
Обновление локальной памяти может сохранять/разрешать уже известные вопросы.
Новые вопросы добавляются только отдельным извлечением из ответа с проверкой точных цитат.

MCP для MLX по умолчанию отключён. Для проверки tool calls можно включить
`LOCAL_LLM_TOOLS_ENABLED=true`; модель/шаблон должны поддерживать инструменты.
Все действия по-прежнему требуют подтверждения точных параметров.
После изменения переменных перезапустите backend; после изменения порта/модели — MLX.
Один ход с памятью и guards состоит из нескольких генераций и может занимать несколько минут.
`CHAT_STREAM_TIMEOUT_SECONDS=900` задаёт общий SSE-таймаут (30–3600 секунд);
`LOCAL_LLM_TIMEOUT_SECONDS=180` — таймаут одного вызова MLX. При использовании Nginx
его proxy_read_timeout должен позволять ждать вспомогательные генерации; SSE buffering остаётся выключенным.

## Самопроверка

1. Уберите OPENAI_API_KEY и перезапустите backend.
2. Создайте чат Local MLX без RAG/MCP и отправьте: «Мой проект называется Маяк».
3. Отправьте: «Как называется мой проект?» — модель должна использовать историю.
4. Обновите страницу: история и Local MLX должны сохраниться.
5. Остановите MLX, отправьте сообщение: появляется ошибка, текст доступен для повтора.
6. Запустите MLX и повторите сообщение: один завершённый ход сохраняется в истории.

Автоматическая проверка реального сервера (только локальные запросы):

```bash
mvn -Dtest=LocalMlxConversationModelTest -Dmlx.live=true test
```

---

> Команда `python -m mlx_vlm.generate ...`, которую ты выполнил, запускает **одиночную генерацию**, а не сервер. Для постоянного локального API используй `mlx_lm.server`.
