# Архитектура

## Назначение

Веб-приложение AI Advent Challenge — harness для диалоговых агентов. Сервер написан
на Java 21 и Spring Boot 4; UI — React 19 и Vite. Основной HTTP API и потоковые ответы
обслуживает Spring MVC/SSE. В production React-сборка включается в исполняемый JAR.

## Основные подсистемы

- `agent`: каталог ролевых YAML-конфигураций, чаты, стратегии контекста, рабочая и
  долговременная память, управление этапами задачи и подключение ConversationModel.
- `harness`: настройки запроса/чата, подготовка RAG-контекста, хранение usage и
  маршруты SSE для обычных сообщений и подтверждения MCP.
- `rag`: загрузка PDF/DOC/DOCX/Markdown, извлечение текста, chunking, embedding, индексы,
  retrieval, reranking и серверная проверка ссылок/дословных цитат.
- `mcp`: Spring AI MCP client, discovery инструментов и выполнение с явным
  подтверждением конкретных аргументов.
- `user`: регистрация, Basic-аутентификация и профиль.
- `health`: ограниченные проверки PostgreSQL, OpenAI,
  embedding-сервиса, reranker и MCP.
- `frontend`: SPA с чатом, памятью/настройками, RAG и MCP; Vite проксирует `/api`
  во время разработки.

Пакеты в `src/main/java/com/github/vladsaraykin/aichat/` разделены на `api`,
`application`, `domain` и `infrastructure`; внешние вызовы изолированы в адаптерах.
REST-контроллеры не вызывают LLM напрямую.

## Запрос в чате

1. Backend проверяет владельца чата и фиксирует snapshot настроек.
2. Если включён RAG, запрос уточняется по истории/памяти, строится embedding,
   PostgreSQL возвращает кандидатов, reranker фильтрует/ранжирует их.
3. Контекст создаётся выбранной стратегией: Summary, Sliding Window, Sticky Facts
   или Branching. Полная история при этом хранится отдельно.
4. Основной агент получает только инструменты выбранных MCP-серверов; каждый
   инструментальный вызов ждёт отдельного подтверждения пользователя.
5. Для RAG-ответа сервер проверяет JSON-структуру, source references и дословность
   цитат до публикации результата. Цитатная проверка подтверждает происхождение,
   но не семантическое следование каждого утверждения.
6. Завершённый ход, память и usage сохраняются в PostgreSQL; SSE передаёт статусы,
   частичный текст и результат. Незавершённый ответ не сохраняется.

Модели, reasoning effort и тарифы централизованы в `agent-defaults.yaml`, а не
задаются отдельно для каждой роли. Новые чаты используют общий default; выбранная
модель существующего чата хранится в настройках чата. OpenAI ключ и все провайдерские
вызовы остаются только на backend.

## Данные и границы

PostgreSQL — основное постоянное хранилище. Flyway применяет SQL-файлы
`src/main/resources/db/rag/migration`; автоматической очистки данных миграции не
делают. Данные аккаунтов и RAG-документов изолированы по `owner_username`.
Оригиналы загруженных документов хранятся в PostgreSQL; временный scratch-файл
используется при извлечении текста.

Поддерживается один backend-инстанс. Локальные блокировки/очереди не образуют
распределённый протокол блокировок.
