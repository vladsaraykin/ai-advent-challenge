## Сеть и безопасность

- PostgreSQL доступен только с разрешённых адресов через `pg_hba.conf` и firewall;
  ранее на VM использовалась цепочка `PG_MAC_ACCESS`. Правила зависят от текущего
  внешнего IP и должны быть проверены администратором VM.
- Для PostgreSQL/Ollama/reranker предпочтительны LAN, VPN или SSH-туннель. Не
  публикуйте порты `5432`, `11434` и `18090` через роутер: эти сервисы не рассчитаны
  на неаутентифицированный доступ из Интернета.
- Reranker endpoint не имеет пользовательской аутентификации. Ограничьте его
  firewall-ом адресом backend.
- Basic Auth используется для профилей приложения; удалённый доступ должен идти по
  HTTPS. Секреты, пароли и API-ключи не хранятся в этой документации.
- Если меняется внешний IP клиента, обновите firewall/allowlist и `pg_hba.conf`;
  сначала проверьте TCP, затем PostgreSQL SSL mode и точную запись `pg_hba.conf`.

## PostgreSQL/RAG

Схема `rag` создаётся Flyway; PostgreSQL с pgvector необходим для приложения в целом.
`RAG_ENABLED=false` отключает retrieval UI/API, но не устраняет зависимость от
PostgreSQL. Размер пула задаётся `RAG_DATABASE_POOL_SIZE` (допустимо 1–50; типичное
значение проекта — 50). Пароль обязателен и не должен передаваться в аргументах
команд, логах или Git.

Документы и их индексы принадлежат профилю. Один документ может иметь несколько
индексных запусков; при retrieval выбирается подходящий завершённый индекс. Загрузка
в текущем UI поддерживает PDF, DOC и DOCX; backend также принимает Markdown для
автоматической синхронизации проекта. OCR сканированных PDF
не предусмотрен.

## RAG параметры

- Embedding: Ollama `embeddinggemma`, вектор 768 измерений.
- Vector candidates: 20 по умолчанию.
- Reranker: `cross-encoder/mmarco-mMiniLMv2-L12-H384-v1`, sigmoid score 0–1.
- Порог по умолчанию: `0.2`, финальный top-K: `5`.
- Эти score не являются вероятностью правильности. Порог требует проверки на
  контрольных вопросах проекта.

Официальные инструкции развертывания сервисов находятся в `deploy/rag-gpu/` и
`deploy/reranker/`.
